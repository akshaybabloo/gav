# Tasks: Playlist Redesign

**Input**: Design documents from `specs/002-playlist-redesign/`

**Prerequisites**: [plan.md](./plan.md), [spec.md](./spec.md), [research.md](./research.md), [data-model.md](./data-model.md), [contracts/](./contracts/), [quickstart.md](./quickstart.md)

**Tests**: Included. Constitution Principle V requires unit tests for all non-GUI logic, and
[quickstart.md](./quickstart.md#automated-checks) lists the required suites. UI behaviour is
checked by the manual quickstart scenarios referenced at each checkpoint.

**Tracking issue**: #191. Each phase names its issue and branch; close the issue from its PR.

**Organization**: Tasks are grouped by user story. The Foundational phase is the model swap with
no visible change ([plan.md → Delivery order](./plan.md#delivery-order), step 1). Each story after
it is one PR.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependency on unfinished tasks)
- **[Story]**: The user story the task belongs to (US1–US4)

## Path Conventions

GAV keeps every source file at the repository root. QML files belong to the `gavqml` module, and
C++ units are registered in `qt_add_qml_module(appgav … SOURCES …)` in `CMakeLists.txt`. Tests
live in `tests/` and are compiled into the `gav_tests` target. Build and test with `just build`
and `just test`. Code follows the surrounding style with no comments by default (Constitution:
Development Workflow).

## Phase 6: User Story 4 - Manage several items at once (Priority: P4)

**Independent Test**: With 10 items, select three and remove them, drag another to a new position,
