# Quickstart: Validating the Playlist Redesign

How to prove each user story works end to end. Automated checks come first, then manual scenarios
for behaviour that cannot reasonably be automated (Constitution Principle V). Contracts and data
rules are linked, not repeated.

## Prerequisites

- A GAV build: `just build` (see `CLAUDE.md`). No new dependencies.
- Test data in `tests/data/` (added by the implementation):

| File | Purpose |
|------|---------|
| `multi.mkv`, `styled.mp4` | Existing local videos |
| `tone.mp3` | A short local audio file |
| `mixed.m3u8` | Local video, local audio, one on-demand stream address, one live stream address, one missing local file, two entries with the same location, entries with and without `group-title`, one `#EXTGRP` entry, one `tvg-logo` |
| `channels-10k.m3u8` | Generated by `tests/data/generate-playlist.sh 10000`: 10,000 stream entries in 40 groups with attributes in the IPTV style. Not committed. |

- For stream rows, any reachable HLS address. The on-demand and live entries in `mixed.m3u8` can
  be edited to addresses that work on the day.

## Automated checks

```bash
just test
```

These must pass on all CI platforms:

| Suite | Covers |
|-------|--------|
| `PlaylistModelTest` | Append and insert in one batch, remove with undo, block move, duplicates, current entry across changes, queue (order, unavailable entries skipped), `setLoaded` / `setUnavailable`, model consistency (`QAbstractItemModelTester`) |
| `PlaylistViewTest` | Search on title and group, the filters, the three sort orders, grouping with counts and collapse, `canReorder`, selection rules, `nextRow` / `previousRow` skipping headers, collapsed groups and unavailable entries, repeat wrap, mapping both ways |
| `PlaylistIOTest` (extended) | `group-title`, `tvg-logo`, `#EXTGRP`, attribute text kept verbatim, group written back, missing local files kept as unavailable, read-write round trip ([contract](./contracts/playlist-format.md)) |
| `ShuffleOrderTest` (adapted) | Id-based order, `setCandidates` keeping history, no repeats until exhausted |
| `PlaylistViewTest.RebuildTimeIsLogged` | Prints search, sort and group rebuild times at 10,000 and 50,000 entries (research R3). Informational; SC-003 is judged on a release build. |

## Manual scenarios

Run with `just run`. Each row is one check.

### Story 1: browse and switch while watching

| # | Steps | Expected |
|---|-------|----------|
| Q1.1 | Start GAV with no arguments | The playlist fills the content area with the empty state explaining files, playlists and addresses (FR-005) |
| Q1.2 | Open `mixed.m3u8`, play the first video, press `Ctrl+L` | A panel opens on the right over the video. The video keeps playing and the rest of the picture stays visible (FR-002, SC-001) |
| Q1.3 | Double-click another entry in the panel | It plays. The panel stays open and marks the new entry as playing (FR-008) |
| Q1.4 | Click the visible part of the video | The panel closes. Playback does not pause (FR-002a) |
| Q1.5 | Open the panel, press `Esc`; press `Esc` again in full screen | First `Esc` closes the panel, the second leaves full screen |
| Q1.6 | Drag the panel's left edge, close GAV with the panel open, start it again and play a video | The panel reopens at the same width (FR-003) |
| Q1.7 | With the panel open, make the window narrower than 560 px (tile it or split the screen; dragging stops at the 640 px minimum, where the panel still leaves part of the picture visible) | The panel takes the full width and shows a close button (FR-004) |
| Q1.8 | Play an audio file | The playlist fills the content area, as before the redesign |
| Q1.9 | Open the mini player | It behaves as before and has no playlist |

### Story 2: rows that tell you what each item is

| # | Steps | Expected |
|---|-------|----------|
| Q2.1 | Open `mixed.m3u8` | Local video, local audio and streams have different icons, show their path or address on line 2 and say their kind in words on line 3 (FR-006, FR-007, SC-005) |
| Q2.2 | Look at the missing local file | Marked "Unavailable – File not found". `N` (next) skips it (FR-009) |
| Q2.3 | Play the on-demand stream, then the live one | The first row gains its duration; the second shows "Live". Neither needed a click on the row (FR-010) |
| Q2.4 | Save the playlist, reopen it | Durations learned in Q2.3 are still shown |
| Q2.5 | Look at a row with a long path, then widen the panel | The path is shortened in the middle with its file name visible, and more of it shows as the panel widens. No tooltip appears on hover (FR-011) |
| Q2.6 | Turn "Show channel logos" off (it is on by default), then watch network activity while scrolling `channels-10k.m3u8` | No image requests are made (FR-012, FR-029) |
| Q2.7 | Turn "Show channel logos" back on | Logos appear for visible rows that have one. Rows whose logo fails show the kind icon, with no error (FR-012a) |
| Q2.8 | Settings → History → Clear history | `<CacheLocation>/logos/` is empty afterwards (FR-012b) |
| Q2.9 | Switch between light and dark theme with the panel open and measure row text, secondary text and icons with a contrast checker; tab through the panel | At least 4.5:1 for text and 3:1 for large text and icons in both themes, and every control shows a focus indicator (FR-013) |

### Story 3: find things in very large playlists

| # | Steps | Expected |
|---|-------|----------|
| Q3.1 | Open `channels-10k.m3u8` | First rows appear within 2 s and the window stays responsive (SC-004, FR-028) |
| Q3.2 | Press `Ctrl+F`, type part of a channel name | The list narrows on each keystroke with no visible lag, and the header shows "N of 10000" (FR-014, SC-003) |
| Q3.3 | Time finding and starting "Channel 7341" from a cold start of the search | Under 10 s (SC-002) |
| Q3.4 | Turn grouping on | 40 group headings with counts. Collapse one: its rows disappear and its count stays (FR-015) |
| Q3.5 | In `mixed.m3u8`, choose each filter in turn | "Local files" and "Streams" show the expected subsets, and there is no Live filter (FR-016) |
| Q3.6 | Sort by title, then by duration, then back to playlist order | The view reorders each time. Saving the playlist while sorted by title writes playlist order (FR-017, FR-027) |
| Q3.7 | Search for text that matches nothing | "Nothing matches" with a button that clears the search and filter (FR-019) |
| Q3.7a | Type in the search box, press `Esc`, then `Esc` again | The first `Esc` clears the search and leaves the panel open; the second closes it (FR-002a) |
| Q3.8 | Search so that three entries remain, play the first, press `N` twice, then `N` again with repeat off | Plays the second and third, then stops. Hidden entries are never played (FR-018) |
| Q3.9 | With a search active and shuffle on, play through the visible entries | Only visible entries play, each once before any repeats |

### Story 4: manage several items at once

| # | Steps | Expected |
|---|-------|----------|

| Q4.5 | Choose "Play next" on two entries, then let the current one end | The two queued entries play in the order queued, then normal order resumes |
| Q4.5a | Queue an available entry and the missing file, then type a search that hides the queued available entry, and let the current one end | The hidden queued entry still plays; the missing file is skipped (FR-022a) |
| Q4.6 | Drop a file between two rows; drop another on the video | The first is inserted at the drop position, the second is appended (FR-023) |
